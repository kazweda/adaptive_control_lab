## Issue #40: STR制御の定常偏差問題 - 根本原因調査

**日付**: 2026年1月23日  
**調査者**: GitHub Copilot  
**関連Issue**: #40 / **前回PR**: #45

### 問題の概要

STR制御を使用した場合、ステップ目標値に対して定常偏差が発生する。特に `targetPole1=0.3` では発散することが確認された。

### 調査結果

#### 1. 問題の再現（Simulator統合テスト）

実行条件: 1次プラント（a=0.8, b=0.5）、目標値=1.0、200ステップ実行

| targetPole1 | 定常出力 y_ss | 偏差 | 状態 |
|------------|-------------|------|------|
| 0.3 | -0.915 | 1.915 | **発散** |
| 0.5 | 0.994 | 0.006 | 軽微な偏差 |
| 0.7 | 1.015 | 0.015 | やや過大 |

#### 2. 根本原因: RLS推定精度の低下

**推定誤差の実測値:**
```
真のパラメータ:  a = 0.800,  b = 0.500
推定値（200ステップ後）: a = 0.899,  b = 0.260
推定誤差:        Δa = 0.099,  Δb = 0.240 (48%の誤差)
```

**推定精度が低い原因:**

1. **issue #37対策の副作用**
   - オーバーフロー対策で `initialCovarianceScale` を 1000 → 100 に縮小
   - RLSの学習速度が低下し、推定収束が遅くなった
   - 不正確な推定値のまま制御が実行される

2. **制御入力飽和による悪循環**
   ```
   初期段階:
   - b推定値が極端に小さい（0.001など）
   → 過大な制御入力が計算される（u > 10）
   → controlInputLimit でクリップ（u = ±10）
   → 真の入出力関係が観測できない
   → RLSの学習が阻害される
   → 推定精度がさらに低下
   ```

3. **不正確な推定値 + 極配置 = 不安定化**
   - 推定パラメータが真値と異なる状態で極配置を実行
   - 意図した極位置とは異なる閉ループ特性になる
   - 特に小さい極（p=0.3など）では不安定化しやすい

#### 3. 理論検証: リファレンスゲインは正しい

**完全な推定値を使用した場合（単体テスト）:**

| targetPole1 | 定常出力 y_ss | 偏差 | 結果 |
|------------|-------------|------|------|
| 0.3 | 1.0000 | 0.0000 | ✅ 正常 |
| 0.5 | 1.0000 | 0.0000 | ✅ 正常 |
| 0.7 | 1.0000 | 0.0000 | ✅ 正常 |

**結論**: PR #45で追加したリファレンスゲイン `(1 - p_d)` は理論的に正しい。問題はRLS推定精度にある。

#### 4. 推定精度の推移

```
ステップ |  a推定誤差  |  b推定誤差  | 出力 y
--------|-----------|-----------|--------
    0   |  0.300    |  0.499    |  0.000
   20   |  0.256    |  0.171    |  3.688  ← 過渡応答で大きく振動
   40   |  0.160    |  0.209    |  0.412
   60   |  0.144    |  0.216    |  0.955
   80   |  0.126    |  0.226    |  0.923
  100   |  0.116    |  0.231    |  0.956
  200   |  0.099    |  0.240    |  0.994  ← 収束が遅く、最終誤差も大きい
  300   |  0.097    |  0.241    |  0.999
```

**観察**:
- b推定値が真値の約半分に収束している（0.26 vs 0.5）
- 学習速度が遅く、300ステップ経過しても10%の誤差が残る

### 解決策の方向性

#### 短期対策

1. **initialCovarianceScaleの最適化**
   - 100 → 500〜1000 に増加（学習速度とオーバーフロー対策のバランス）
   - 初期段階の学習を高速化

2. **段階的な極配置**
   ```
   初期段階（k < 50）: 緩い極（p = 0.7〜0.8）で保守的に制御
   推定収束後（k >= 50）: 所望の極に移行
   ```

3. **制御入力の段階的制限**
   ```
   初期段階: ±1.0 に制限（推定精度が低い）
   推定収束後: ±10.0 に緩和（通常動作）
   ```

#### 中期対策

4. **推定精度モニタリング**
   - 共分散行列のトレース `trace(P)` を計算
   - 信頼度指標として利用: `confidence = 1 / (1 + trace(P))`
   - 信頼度が低い間は保守的な制御

5. **アンチワインドアップ機構**
   - 制御入力が飽和した場合、積分項の更新を停止
   - STRの過去値履歴も飽和値を使用

6. **適応的な忘却係数**
   ```dart
   // 推定誤差が大きい初期段階: λ = 0.95（学習速度優先）
   // 推定収束後: λ = 0.98〜1.0（安定性優先）
   ```

#### 長期対策

7. **Projection Algorithm（射影アルゴリズム）**
   - パラメータ推定値を物理的に妥当な範囲に制約
   - 例: `0 < b < 2`, `0 < a < 1` など

8. **Dead Zone（不感帯）の導入**
   - 推定誤差が小さくなったら学習を停止
   - パラメータドリフトを防止

### 前回対応（PR #45）の評価

**正しかった点:**
- リファレンスゲイン `(1 - p_d)` の理論は正しい
- 単体テストでは完璧に動作

**見落としていた点:**
- RLS推定精度の問題を考慮していなかった
- 統合テスト（Simulator使用）が不足していた
- issue #37対策の副作用を見逃していた

**教訓:**
- 制御理論の正しさと実装の正しさは別物
- 単体テストだけでなく統合テストが必須
- パラメータ調整の副作用を常に検証する
