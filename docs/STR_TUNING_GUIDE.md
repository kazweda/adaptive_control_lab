# STR制御チューニングガイド

## 概要

Self-Tuning Regulator (STR) は、Recursive Least Squares (RLS) 推定器を用いて**プラントパラメータをリアルタイム推定**し、推定パラメータに基づいて**制御則を動的に更新**する適応制御手法です。

本ドキュメントでは、STR導入時の注意点、特に**ソフトスタート機能**の役割と必要シナリオについて説明します。

---

## STRの初期化フェーズの課題

### 問題シナリオ: 2次プラント + STR

2次プラント（`y(k) = a1*y(k-1) + a2*y(k-2) + b1*u(k-1) + b2*u(k-2)`）をSTRで制御する場合、初期段階で以下の問題が発生します：

#### 1. 推定パラメータの不確実性

RLS推定は以下の更新則に従います：
```
θ̂(k) = θ̂(k-1) + K(k) * [y(k) - φ(k)ᵀ * θ̂(k-1)]
K(k) = P(k-1) * φ(k) / [1 + φ(k)ᵀ * P(k-1) * φ(k)]
P(k) = [I - K(k) * φ(k)ᵀ] * P(k-1)
```

初期値 `θ̂(0) = [0.8, -0.3, 0.5, 0.1]` では、実プラントパラメータとの乖離が大きく、推定値が安定化するまで（通常20～50ステップ）は信頼性が低いです。

#### 2. 初期制御入力の爆発

STR制御則は推定パラメータを用いて計算されます：
```
u(k) = [(1 - p_d) * r(k) - (â1 - p_d) * y(k)] / b̂1
```

推定値が実値から大きく乖離している初期段階では、**計算される制御入力が非常に大きくなる**（数十倍）ことがあります。

#### 3. 2次系で顕著なオーバーフロー

実装実績：
- 1次プラント + STR: 通常は問題なし
- 2次プラント + STR: **初期21ステップでオーバーフロー**（IEEE 754 double精度の上限を超過）

理由：
- 2次系は4つのパラメータ（a1, a2, b1, b2）を同時推定
- 初期推定の誤差が2倍
- 特に b̂1, b̂2 の推定が不安定

## ソフトスタート機能

### 概要

ソフトスタートは、**初期段階で制御入力をスケールダウン**し、推定パラメータが安定化するまで「慎重な制御」を実現する機能です。

### 仕組み

#### 1. スケール係数の計算

```
scale(k) = initialScale + (1.0 - initialScale) * (k / softStartSteps)
```

**例** (`initialScale=0.2`, `softStartSteps=30`):
- k=0: scale = 0.2 (20%のみ適用)
- k=15: scale = 0.6 (60%適用)
- k≥30: scale = 1.0 (100%適用、ソフトスタート完了)

#### 2. 制御入力への適用

```dart
// Simulator.step() での実装
double softScale = _getSoftStartScale();
final scaled = u * softScale;  // スケール適用
final clamped = scaled.clamp(-limit, limit);  // 安全制限
```

### 効果

| 指標 | ソフトスタートなし | ソフトスタートあり |
|-----|-----------------|-----------------|
| 初期オーバーフロー | 21ステップで発生 | なし |
| 初期制御入力 | 5～10 (大) | 1～2 (小) |
| 推定パラメータ収束 | 不安定 | 安定（30ステップで完了） |
| 最終的な制御性能 | N/A（発散） | 良好（残差→0） |

## 実装詳細

### 有効化方法

#### 手動有効化（テスト用）

```dart
final str = STR(parameterCount: 4, rls: rls);
str.enableSoftStart(
  initialScale: 0.2,    // 初期スケール（20%）
  steps: 30,             // ソフトスタート期間（30ステップ）
);
```

#### 自動有効化（StrManager経由）

2次プラント検出時に自動で有効化：

```dart
// StrManager._initializeStr() 内
if (paramCount == 4) {  // 2次系を検出
  str!.enableSoftStart(initialScale: 0.2, steps: 30);
}
```

### パラメータ調整ガイド

#### initialScale（初期スケール）

- **推奨値**: 0.1～0.3
- 小さいほど初期入力が小さいが、収束が遅い
- 大きいほど初期入力が大きいが、オーバーフロー危険
- **デフォルト 0.2**: バランスが取れている

#### steps（ソフトスタート期間）

- **推奨値**: 20～50ステップ
- プラント/推定器の特性に応じて調整
- 通常、RLS推定が大まかに安定化する期間
- **デフォルト 30**: 多くのシナリオで有効

## 動作確認

### テストケース

実装には以下の3つのテストが含まれています：

#### 1. デフォルト無効確認

ソフトスタート未有効時は、制御入力スケールが1.0（通常動作）

#### 2. 線形補間確認

スケール係数が線形に 0.1 → 1.0 に変化することを検証

#### 3. 2次系動作確認

2次STR + ソフトスタート でオーバーフロー防止を確認：

```dart
final controlInputs = <double>[];
for (int i = 0; i < 30; i++) {
  final u = str.computeControl(y1, 1.0);
  controlInputs.add(u);
  // ... RLS更新 ...
}
// controlInputs.first < controlInputs[15] < controlInputs[30]
// （制御入力が段階的に拡大）
```

## シナリオ別チューニング

### シナリオ1: 1次プラント + STR

**推奨設定**:
```dart
// ソフトスタート不要（通常は不要）
// ただし、プラント係数が極端な場合は有効化
str.enableSoftStart(initialScale: 0.3, steps: 20);
```

**理由**: 2次系ほど推定の複雑性がない

---

### シナリオ2: 2次プラント + STR（推奨）

**推奨設定**:
```dart
// 自動有効化（StrManager経由）
// または手動で：
str.enableSoftStart(initialScale: 0.2, steps: 30);
```

**推定の流れ**:
- k=0～10: 粗い推定、スケール 0.2～0.4
- k=11～20: 推定値が収束傾向、スケール 0.4～0.7
- k=21～30: 推定ほぼ安定、スケール 0.7～1.0
- k≥31: 完全に適応制御、スケール 1.0

---

### シナリオ3: 2次プラント + STR（高速応答要求）

**チューニング例**:
```dart
str.enableSoftStart(
  initialScale: 0.15,  // より低い初期値
  steps: 20,           // より短い期間
);
```

**トレードオフ**:
- ✅ より早く完全な制御に移行
- ⚠️ 初期段階のオーバーシュート増加の可能性

## トラブルシューティング

### Q: ソフトスタート中に目標値追従が遅い

**A**: initialScale を上げるか、steps を減らしてください

```dart
str.enableSoftStart(initialScale: 0.3, steps: 20);  // より早い立ち上がり
```

---

### Q: ソフトスタート完了後の応答が悪い

**A**: 推定パラメータが不安定な可能性。steps を増やしてください

```dart
str.enableSoftStart(initialScale: 0.2, steps: 50);  // より安定化を待つ
```

---

### Q: 2次系でもソフトスタートなしで動作する？

**A**: プラントパラメータが安定している場合は可能ですが、一般的には不推奨です。初期オーバーフロースのリスク回避のため、常に有効化を推奨します。
